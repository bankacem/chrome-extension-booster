## Technical Guide: Customizing Extension Permissions via Chrome Policies (Enterprise)  

Chrome Enterprise supports **JSON‑based policy files** that can be pushed through Group Policy (Windows), Mobile Device Management (macOS, Linux), or cloud‑based admin consoles (Google Workspace).  

### Sample Policy for **Privacy Guardian**  

```json
{
  "ExtensionInstallForcelist": [
    "aabbccddeeff001122334455*https://clients2.googleusercontent.com/*"
  ],
  "ExtensionSettings": {
    "aabbccddeeff001122334455": {
      "installation_mode": "force_installed",
      "allowed_permissions": [
        "cookies",
        "webRequest",
        "storage"
      ],
      "blocked_permissions": [
        "management",
        "nativeMessaging"
      ],
      "runtime_allowed_hosts": [
        "https://privacyguardian.io/*"
      ]
    }
  }
}
```

*Key points:*  

- **`allowed_permissions`** limits the extension to only the essentials needed for blocking.  
- **`blocked_permissions`** prevents any future updates from requesting `nativeMessaging` (a known attack vector).  

### Policy for **uMatrix Pro** (Granular Control)  

```json
{
  "ExtensionSettings": {
    "ff1122aa33bb44cc55dd66ee*": {
      "installation_mode": "force_installed",
      "allowed_permissions": [ "webRequest", "storage" ],
      "runtime_allowed_hosts": [ "*://*/*" ],
      "user_script_control": {
        "block_third_party": true,
        "default_allow": false
      }
    }
  }
}
```

**Deploy via:**  

- **Google Workspace Admin console → Devices → Chrome Management → Apps & Extensions**  
- **Microsoft Intune** (use Chrome ADMX)  
- **JAMF Pro** for macOS  

*Tip:* After policy push, verify via `chrome://policy/` that the extension’s `runtime_allowed_hosts` reflect the JSON exactly.
