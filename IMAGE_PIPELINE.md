# Image pipeline

## Production behavior

Running `npm run build` automatically runs `prebuild`, which executes `scripts/optimize-images.mjs` before Vite builds the application. The optimizer scans `public/` for PNG, JPEG, and existing WebP sources, preserves the original source as a fallback, and creates sibling `.webp` and `.avif` files. It limits very large images to 1600×900, uses a bounded concurrency of four workers, and skips variants that are newer than their source.

The generated modern variants are intentionally ignored by Git through `.gitignore`; they are build artifacts and are regenerated by Vercel and GitHub Actions. This keeps the repository smaller while ensuring the deployed `dist/` folder contains the modern formats.

## Runtime behavior

`src/components/ResponsiveArticleImage.tsx` emits a `<picture>` element with AVIF first, WebP second, and the original source as fallback. It also sets stable dimensions, asynchronous decoding, and configurable loading priority. Blog card images use lazy loading except for the first visible card; article hero images use eager loading and high fetch priority.

## Adding a new editorial image

Place the original image in `public/content/images/` or a generated subdirectory. Use a stable JPEG or PNG source, preferably close to a 16:9 editorial ratio. Set the article `featured_image` to the public path. The next production build creates the AVIF and WebP siblings automatically. Do not commit generated `.avif` or `.webp` files.

For a new AI-generated editorial cover, keep the image text-free, avoid trademarks and recognizable product interfaces, and use descriptive alt text from the article title. Run `npm run build`, `npm run test:performance`, `npm run test:seo`, and `npm run test:links` before publishing.

> **2026-09-04 update:** Vercel prebuild skips the optimizer (`scripts/prebuild.mjs`), so `.webp`/`.avif` derivatives referenced by articles ARE committed to the repo (force-added past `.gitignore`). If you add new JPEG/PNG sources, either run `node scripts/optimize-images.mjs` locally and commit the derivatives, or temporarily re-enable the optimizer on Vercel.
