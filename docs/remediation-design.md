**التاريخ:** 2026-10-05 · **المرجع:** رسالة المالك 2026-10-05 (بنود 1–4) · **الحالة:** docs فقط، دمج ذاتي مشروط

## 0) القواعد المطلقة الحاكمة (لا تُخترق بقياس عملية)

1. **ممنوع حذف أو إعادة تسمية أي مقال أو صورة** — على main وكل الفروع، مهما كانت السبب.
2. **ممنوع تغيير أي slug أو متن مقال أو صورة أو رابط** — الاستثناء الوحيد الحالي: PR مسودة واحد (`frontmatter-honesty-batch-1` = PR **#484**) يعدّل أربعة حقول نصية فقط (`title`, `seo_title`, `meta_description`, `excerpt`) في تسعة مقالات، **ولا يُدمج إلا بيد المالك**.
3. كل تعديل مستقبلي على أي مقال يحتاج موافقة كتابية من المالك، ويُنفَّذ بصيغة PR مسودة ما لم يُصرَّح بغير ذلك.
4. لا نشر، لا تفعيل daily-article أو cron، لا دمج #447 #448 #450 #451 #439، لا مفاتيح، لا push مباشر إلى main، لا استدعاءات نموذج.

## 5) بقايا تحتاج قرار المالك

1. **حقل `description` الملفي** (خارج الحقول الأربعة المسموحة) ما زال يحمل "I tested…" في مقالين من الدفعة (`adblock-chrome-android-complete-guide-2026`، `chrome-extensions-on-android-2026-guide`). الفهرس العامّ يشتق `description` من `meta_description` — لكن الحقل يبقى في الملف. القرار: تمديد الدفعات القادمة ليشمل `description` بموافقة صريحة.
2. **ربط slug-redirects.json فعلياً** (wiring) ليخدم 301 داخلياً بدل الاعتماد على vercel.json وحده — تحسين اختياري، يحتاج قراراً لأنه يلمس طبقة الخدمة.
3. **إعادة طلب الفهرسة في GSC** بعد دمج المالك لـ#484 (يد المالك).

## 6) التراجع والسلامة

- كل PR معالجة = فرع مستقل + كوميت squash واحد → التراجع بـ`git revert` واحد لكل دفعة، بلا أي أثر جانبي.
- لا مسودة تُدمج آلياً؛ الدمج بيد المالك حصراً (عدا دمج الكود/docs المشروط المصرَّح به).
- كل الفحوصات حتمية بلا استدعاءات نموذج، وسكربتاتها محفوظة خارج المستودع (`scripts/*.py` في بيئة العمل) ويمكن إعادة تشغيلها بأي وقت لإعادة الإثبات.
