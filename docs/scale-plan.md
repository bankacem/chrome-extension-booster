# خطة التوسّع: تحييد المتن على المقالات الـ398 (تصميم فقط — بلا تنفيذ)

**الحالة:** تصميم بانتظار قرار المالك. لا شيء هنا منفَّذ — لا workflow جديد، لا استدعاءات نماذج، لا كود جديد خارج هذا المستند.

**الهدف:** تطبيق عملية تحييد المتن نفسها التي جُرِّبت يدوياً في `body-honesty-pilot-1` على المقالات الـ398 ذات ادعاء الاختبار في المتن، عبر cleanapis، مع بقاء القرار والدمج بيد المالك.

---

## 1) الشكل العام: workflow_dispatch جديد

ملف مقترح: `.github/workflows/body-neutralization-batch.yml` (لا يُنشأ الآن).

- **المُشغِّل:** `workflow_dispatch` فقط (لا cron، لا push، لا PR trigger) بمدخلات:
  - `batch_id` (معرّف الدفعة، يحدد ملف قائمة المقالات في docs)
  - `dry_run` (bool، افتراضياً true — يولّد التقرير بدون أي استدعاء نموذج وبكلفة صفر)
- **الأذونات:** `permissions: contents: read` على مستوى الـworkflow بالكامل. لا `write` — الـworkflow **لا يعمل commit ولا يفتح PR ولا يلمس الفروع**؛ كل المخرجات تُرفع كـartifacts فقط.
- **السر:** `CLEANAPIS` (موجود أصلاً في GitHub Secrets) يمرَّر كمتغير بيئة `CLEANAPIS_KEY` لخطوة الاستدعاء وحدها — لا يُطبع ولا يُكتب في أي artifact.

## 2) خطوات التشغيل لكل مقال (حتمية حول النموذج)

1. **تحديد الفقرات المعلَّمة:** فحص حتمي بالبوابات المدموجة (S1 نشط + المقترح + أنماط البلاغ الأول-شخص) ينتج مؤشرات الفقرات المعلَّمة — نفس منهجية `body_claims_tiers.json`.
2. **بناء الحزمة:** الفقرات المعلَّمة فقط + عنوان المقال وحقول frontmatter الأربعة كسياق + قواعد التحييد (حذف سرد الاختبار أو تعميمه بلا أرقام جديدة، صياغة الإفصاح المعتمدة) — لا يُرسل المتن الكامل.
3. **استدعاء واحد للنموذج** بدور WORKER (`deepseek-v4-pro-0813`) يعيد النص المحيَّد للفقرات المعلَّمة (مخطط JSON صارم: {paragraph_index, new_text}).
4. **التركيب والتدقيق:** تُركَّب النصوص على المتن الأصلي ثم يُشغَّل `body_neutralization_gate` (البوابات السبع: أرقام/أسماء علم/روابط/بنية/فقرات غير معلَّمة/هبوط الكلمات 45%/لا إصابات S1-S2-S3 جديدة).
5. **النتيجة:**
   - نجاح → يُسجَّل في التقرير (قبل/بعد + نتيجة الحارس + إحصاءات).
   - فشل → إعادة محاولة واحدة بدور CRITIC (`glm-5.3`) لإصلاح الانتهاكات المسماة؛ فشل ثانٍ → **يُستبعد المقال من الدفعة ويُسجَّل** (لا يُكرَّس وقت ولا تكلفة إضافية).

**مخرجات الـworkflow (artifacts فقط):** `batch-<id>/report.json` (لكل مقال: قبل/بعد، الفقرات، نتيجة الحارس، الاستبعادات) + `diffs.patch` (patch موحّد لكل مقال — هو ما يفتح منه المالك الـPR يدوياً) + `cost.json` (عدّاد التوكنات والتكلفة المتراكمة). احتفاظ 30 يوماً.

**جداول القياسات المخترعة:** الحارس يمنع تعديلها؛ التقرير يسردها (عنوان + عدد صفوف) لقرار المالك — كما في الـpilot.

## 3) التكلفة التقديرية (أرضية أسعار الإدخال فقط)

أسعار `models.json` (الإدخال بالدولار/مليون توكن؛ **أسعار الإخراج غير معلنة = null**، و`price_confirmed_by_owner=false` → كل رقم أدناه **أرضية دنيا غير مؤكدة**):

| الدور | النموذج | إدخال $/1M | الاستخدام |
|---|---|---|---|
| WORKER | deepseek-v4-pro-0813 | 0.552 | استدعاء التحيين الأساسي |
| CRITIC | glm-5.3 | 1.357 | إعادة محاولة واحدة عند فشل الحارس فقط |
| FAST | gpt-5.6-luna | 0.3565 | (بديل WORKER للدفعات التجريبية) |

**تقدير التوكنات لكل مقال:** الفقرات المعلَّمة ~21.5 سطراً/مقال (متوسط الـ398) ≈ 300 كلمة ≈ 400 توكن + ترويسة تعليمات وقواعد ≈ 700 توكن + سياق (frontmatter + جمل مجاورة) ≈ 600 توكن ≈ **~1,700 توكن إدخال/استدعاء**.

| البند | الحساب (أرضية إدخال فقط) |
|---|---|
| مقال واحد (WORKER فقط) | 1,700 × $0.552/1M ≈ **$0.00094** |
| مقال مع إعادة CRITIC (احتمال ~15%) | +1,900 × $1.357/1M ≈ +$0.0026 |
| متوسط متوقع/مقال | ≈ **$0.0013** |
| الدفعة الكاملة 398 مقالاً | ≈ **$0.52 أرضية** |
| تصحيح عدم يقين الإخراج | بافتراض سعر إخراج = 3× الإدخال (نمط السوق، غير مؤكد): ≈ **$1.5–3 للدفعة الكاملة** |

**السقوف (تُملأ في `caps` عند التنفيذ):** `max_usd_per_article: 0.02`؛ `max_usd_per_run: 2.00` لدفعة ~100 مقال (أرضية ≈ $0.13)؛ `RUN_COST_CAP_USD: 5.00` يبقى سقف الـeval العام. أي تجاوز → `BudgetExceeded` → إيقاف الدفعة فوراً (السلوك الموجود في agents_v2). **`dry_run=true` أولاً: صفر استدعاءات وصفر تكلفة** للتحقق من الفقرات المعلَّمة والحزمة.

## 4) الدفعات

- **الترتيب:** المستوى 1 الجديد (21 مقالاً، ترتيب الأولوية في `body-claims-tiers.json`) ثم المستوى 2 بنفس الترتيب.
- **الحجم:** 8 دفعات × ~50 مقالاً (batch-01 … batch-08)؛ قائمة كل دفعة تُثبَّت في ملف docs قبل التشغيل ليبقى الـdispatch قابلاً للإعادة.
- **الحد الأقصى للاستدعاءات/المقال:** 2 (WORKER + CRITIC إعادة واحدة) — `max_model_calls_per_article: 2`.

## 5) مراجعة عينة 10% من كل دفعة (بيد المالك)

1. **اختيار حتمي:** من قائمة الدفعة مرتبة بالأولوية، تُختار كل عاشر مقال (المواضع 1، 11، 21…) — بلا عشوائية ولا حاجة لseed؛ العينة ≈ 5 مقالات لكل دفعة من 50.
2. **ما يراجعه المالك:** من artifact الدفعة — قبل/بعد كل مقال في العينة + نتيجة الحارس + قائمة الجداول المعلَّقة + أي فقرات استُبعدت.
3. **قاعدة المرور:** العينة تمر بمراجعة المالك 100% → الدفعة "قابلة للـPR"؛ أي ملاحظة → تُصحَّح قواعد التحييد (prompt/حارس) وتُعاد العينة قبل النظر في بقية الدفعة.
4. **الـPR:** يفتحه المالك يدوياً من `diffs.patch` (الـworkflow لا يفتح شيئاً) — كل PR يمس public/content فالدمج بيد المالك حصراً، ويخضع لفحوصات الحارس مرة أخيرة داخل الـPR.

## 6) المخاطر والضوابط

- **أسعار الإخراج غير معلنة:** عدّاد التوكنات هو المقياس الوحيد الموثوق حتى يؤكدها المالك في models.json (`price_confirmed_by_owner=true`).
- **انقطاع cleanapis:** نمط الجلسات السابق (502 متكرر) → بعد 3 محاولات أسية تتوقف الدفعة كاملة (لا استدعاء رابع)؛ المقالات المكتملة تبقى في الـartifact.
- **جودة التحييد:** الحارس الحتمي + عينة 10% + سقف استدعاءين — والخيار الأبدي: إخراج المقال من الدفعة.
- **حدود مسؤول الـworkflow:** قراءة فقط + artifacts — لا كتابة للمستودع إطلاقاً.
